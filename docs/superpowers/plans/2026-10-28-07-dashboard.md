# Plan 07 — API Routes, Dashboard Page & Operator Doc Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the same report live in the dashboard, give the operator the
controls they need to set it up, and write down what the report can and cannot
prove.

**Architecture:** The page reads the same report object the email renders from,
through new API routes behind the dashboard's existing auth — so the screen and
the email cannot disagree. Styling mirrors the dakara-design-system (Neutral DS
v1.12) language in React; its Vue components cannot be imported, so structure
and severity semantics are mirrored, not reused.

**Tech Stack:** Next.js App Router, React, vitest.

**Spec:** `docs/superpowers/specs/2026-10-28-centralized-claude-monitoring-design.md` (§4.2, §5.5a, §5.7, §5.8, §5.9, §7)

**Global Constraints:** see `2026-10-28-00-overview.md`. **Claude only.**

## Review Focus

Covered here:
- Every new route must be unreachable without a dashboard session → Task 1.
- `send-test` performs an outbound action and must be rate-limited → Task 1.
- The page must show `"tak terukur"`, not an empty cell → Task 2.
- The operator doc must state plainly what cannot be measured, or the manager
  will misread the gaps → Task 4.

### Task 1: Monitoring API routes

**Files:**
- Create: `src/app/api/monitoring/report/route.js`
- Create: `src/app/api/monitoring/history/route.js`
- Create: `src/app/api/monitoring/collect/route.js`
- Create: `src/app/api/monitoring/send-test/route.js`
- Test: `tests/unit/monitoring-api-routes.test.js`

**Interfaces:**
- Consumes: `buildReport` (Plan 05); `collectOnce` (Plan 03); `sendReportMail`
  (Plan 06); `getSnapshotsForDate`/`getSnapshotRange` (Plan 02); the dashboard's
  existing auth guard as used by neighbouring dashboard API routes.
- Produces:
  - `GET /api/monitoring/report?date=YYYY-MM-DD` → the report object
  - `GET /api/monitoring/history?connectionId=&days=` → trend series
  - `POST /api/monitoring/collect` → `{ attempted, ok, failed }`
  - `POST /api/monitoring/send-test` → `{ sent, reason? }`, rate-limited

Each route sets `export const dynamic = "force-dynamic"` and
`Cache-Control: no-store`, matching `src/app/api/settings/route.js`.

**Note on "admin-only":** this repo has no roles — auth is one shared dashboard
password or an OIDC/SAML session (spec §7). These routes are therefore reachable
by any dashboard-authenticated user. That is acceptable only because teammates
get API keys, not dashboard logins; the operator doc (Task 4) must say so.

### Task 4: Operator documentation

**Files:**
- Create: `docs/TEAM_MONITORING.md`
- Modify: `CHANGELOG.md`

**Interfaces:** none — prose.

Must cover, per spec §5.8:
1. One-time OAuth of each of the 11 Claude accounts into this instance,
   including the Desktop-only users, so quota is readable. Per-account 2FA needs
   that account's owner present once.
2. Flagging teammates' connections `monitorOnly` so their Pro quota is never
   spent by someone else's request.
3. For Claude Code users: set `ANTHROPIC_BASE_URL` to this instance, use a
   9router API key, and pin that key to their own connection.
4. SMTP setup and the test send.
5. **What the report cannot show** — to be forwarded to the manager with the
   first report: Desktop chat usage yields quota percentages only, never per-seat
   units or cost; the USD figure is an API-price equivalent, not billed spend;
   and sampling coverage limits the trend numbers.
6. **Security:** exposing the gateway to teammates' machines means it is no
   longer localhost-only. Turn on `requireApiKey`. Note that `custom-server.js`
   derives client IP from the TCP socket and strips attacker-controlled
   `X-Forwarded-For`, trusting forwarding headers only from a loopback reverse
   proxy — do not undo this. Note that the dashboard password grants access to
   this report and to every stored connection, so it is not shared with the team.
