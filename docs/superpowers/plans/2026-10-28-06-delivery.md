# Plan 06 — Scheduler & SMTP Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sample hourly, send one report each morning, catch up after downtime,
and never send twice for the same day.

**Architecture:** A persisted due-check rather than a bare interval, so a laptop
asleep at 07:00 still gets that morning's report when it wakes. `lastSentDateKey`
in `kv` is the single guard. Started from `src/instrumentation.js`, which already
guards on `NEXT_RUNTIME === "nodejs"` and starts `startModelCatalogSync()`.

**Tech Stack:** Plain ESM JavaScript, `nodemailer`, vitest.

**Spec:** `docs/superpowers/specs/2026-10-28-centralized-claude-monitoring-design.md` (§5.3, §5.5, §7)

**Global Constraints:** see `2026-10-28-00-overview.md`. **Claude only.**

## Review Focus

Covered here:
- The same `dateKey` must never send twice, including after a restart → Task 2.
- A missed morning must send late, not vanish → Task 2.
- SMTP password must never reach a settings response → Task 3.
- The feature must do nothing at all while disabled → Tasks 2, 3.

### Task 1: Timezone-aware date keys

**Files:**
- Create: `src/lib/monitoring/clock.js`
- Test: `tests/unit/monitoring-clock.test.js`

**Interfaces:**
- Produces:
  - `dateKeyFor(date, timeZone) -> string` — local `YYYY-MM-DD` in that zone.
  - `localHourFor(date, timeZone) -> number` — 0–23.
  - `DEFAULT_TZ = "Asia/Jakarta"`

A UTC day boundary would split an Indonesian working day in half, so this is its
own tested unit rather than inline arithmetic.

- [ ] **Step 1: Write the failing test**

```js
import { describe, expect, it } from "vitest";
import { dateKeyFor, localHourFor, DEFAULT_TZ } from "../../src/lib/monitoring/clock.js";

describe("dateKeyFor", () => {
  it("defaults to Asia/Jakarta", () => {
    expect(DEFAULT_TZ).toBe("Asia/Jakarta");
  });

  it("rolls the day at local midnight, not UTC midnight", () => {
    // 2026-10-28T17:30Z is already 2026-10-29 00:30 in Jakarta (UTC+7).
    expect(dateKeyFor(new Date("2026-10-28T17:30:00Z"), "Asia/Jakarta")).toBe("2026-10-29");
    expect(dateKeyFor(new Date("2026-10-28T16:59:00Z"), "Asia/Jakarta")).toBe("2026-10-28");
  });

  it("gives the same instant a different key in a different zone", () => {
    const t = new Date("2026-10-28T17:30:00Z");
    expect(dateKeyFor(t, "Asia/Jakarta")).toBe("2026-10-29");
    expect(dateKeyFor(t, "UTC")).toBe("2026-10-28");
  });
});

describe("localHourFor", () => {
  it("returns the local hour in the given zone", () => {
    expect(localHourFor(new Date("2026-10-28T00:30:00Z"), "Asia/Jakarta")).toBe(7);
    expect(localHourFor(new Date("2026-10-28T00:30:00Z"), "UTC")).toBe(0);
  });
});
```

### Task 2: Scheduler with due-check and single-send guard

**Files:**
- Create: `src/lib/monitoring/scheduler.js`
- Test: `tests/unit/monitoring-scheduler.test.js`

**Interfaces:**
- Consumes: `collectOnce` (Plan 03); `dateKeyFor`/`localHourFor` (Task 1);
  `pruneSnapshotsOlderThan` (Plan 02, Task 2); `getMeta`/`setMeta` from
  `src/lib/db/helpers/metaStore.js` for `lastSentDateKey`.
- Produces:
  - `tick(deps) -> Promise<{ sampled: boolean, sent: boolean, pruned: boolean, reason: string }>`
    — one scheduler beat, fully injectable.
  - `startScheduler(deps) -> () => void` — starts the interval, returns a stop
    function. Refuses to start twice in one process.
  - `SAMPLE_INTERVAL_MS = 3600000`, `RETENTION_DAYS = 90`

- [ ] **Step 1: Write the failing test**

```js
import { describe, expect, it, vi } from "vitest";
import { tick, startScheduler } from "../../src/lib/monitoring/scheduler.js";

const deps = (over = {}) => ({
  enabled: true, timeZone: "Asia/Jakarta", reportHour: 7,
  now: () => new Date("2026-10-28T01:00:00Z"),   // 08:00 Jakarta
  lastSentDateKey: null,
  collectOnce: vi.fn(async () => ({ attempted: 2, ok: 2, failed: 0 })),
  sendReport: vi.fn(async () => true),
  setLastSentDateKey: vi.fn(async () => {}),
  ...over,
});

describe("tick", () => {
  it("does nothing at all while the feature is disabled", async () => {
    const d = deps({ enabled: false });
    const r = await tick(d);
    expect(r).toMatchObject({ sampled: false, sent: false });
    expect(d.collectOnce).not.toHaveBeenCalled();
    expect(d.sendReport).not.toHaveBeenCalled();
  });

  it("samples on every tick", async () => {
    const d = deps({ now: () => new Date("2026-10-28T06:00:00Z") }); // 13:00, not report hour
    const r = await tick(d);
    expect(d.collectOnce).toHaveBeenCalledTimes(1);
    expect(r.sampled).toBe(true);
    expect(r.sent).toBe(false);
  });

  it("sends once the local report hour has passed and nothing was sent today", async () => {
    const d = deps();
    const r = await tick(d);
    expect(r.sent).toBe(true);
    expect(d.setLastSentDateKey).toHaveBeenCalledWith("2026-10-28");
  });

  it("never sends twice for the same local day", async () => {
    const d = deps({ lastSentDateKey: "2026-10-28" });
    const r = await tick(d);
    expect(r.sent).toBe(false);
    expect(d.sendReport).not.toHaveBeenCalled();
  });

  it("catches up when the machine was asleep at the report hour", async () => {
    // 10:00 Jakarta, report hour 07:00, nothing sent yet today -> send now.
    const d = deps({ now: () => new Date("2026-10-28T03:00:00Z"), lastSentDateKey: "2026-10-27" });
    expect((await tick(d)).sent).toBe(true);
  });

  it("collapses a multi-day backlog into one report for today", async () => {
    const d = deps({ lastSentDateKey: "2026-10-20" });
    await tick(d);
    expect(d.sendReport).toHaveBeenCalledTimes(1);
    expect(d.setLastSentDateKey).toHaveBeenCalledWith("2026-10-28");
  });

  it("does not send before the report hour", async () => {
    // 05:00 Jakarta
    const d = deps({ now: () => new Date("2026-10-27T22:00:00Z"), lastSentDateKey: "2026-10-26" });
    expect((await tick(d)).sent).toBe(false);
  });

  it("still records the send when sampling failed, and vice versa", async () => {
    const d = deps({ collectOnce: vi.fn(async () => { throw new Error("db locked"); }) });
    const r = await tick(d);
    expect(r.sampled).toBe(false);
    expect(r.sent).toBe(true);        // a bad sample must not suppress the report
  });

  it("prunes past the retention window after sending, not on every tick", async () => {
    // 90 days, spec §5.1. Pruning hourly would be wasted writes; never
    // pruning lets ~/.9router grow without bound.
    const prune = vi.fn(async () => 0);
    const sent = await tick(deps({ pruneSnapshotsOlderThan: prune }));
    expect(sent.sent).toBe(true);
    expect(prune).toHaveBeenCalledWith("2026-07-30");   // 90 days before 2026-10-28

    prune.mockClear();
    await tick(deps({ lastSentDateKey: "2026-10-28", pruneSnapshotsOlderThan: prune }));
    expect(prune).not.toHaveBeenCalled();
  });

  it("does not let a failing prune suppress the report", async () => {
    const d = deps({ pruneSnapshotsOlderThan: vi.fn(async () => { throw new Error("locked"); }) });
    expect((await tick(d)).sent).toBe(true);
  });
});

describe("startScheduler", () => {
  it("refuses to start twice in one process", async () => {
    const stop1 = startScheduler(deps());
    const stop2 = startScheduler(deps());
    expect(stop2).toBe(null);          // Next dev-mode double-invocation
    stop1();
  });
});
```

- [ ] **Step 3: Implement `tick`, `startScheduler` and `SAMPLE_INTERVAL_MS` in `src/lib/monitoring/scheduler.js`**

≥ `reportHour`, and `lastSentDateKey !== todayKey`. After a successful send it

double start with a module-level flag on `global`, matching how `usageRepo.js`
keeps cross-module state.

```js
import { describe, expect, it, vi } from "vitest";
import { sendReportMail } from "../../src/lib/monitoring/mailer.js";

const report = {
  dateKey: "2026-10-28", rows: [], footnotes: ["a", "b", "c"],
  summary: { atRiskCount: 1, measuredCount: 1, unmeasuredCount: 9, limitDaysThisWeek: 2 },
  coverage: { samplesTaken: 20, samplesExpected: 24, percent: 83, partial: true },
};
const config = {
  enabled: true, host: "smtp.test", port: 587, secure: false,
  user: "u", pass: "p", from: "bot@t.io", to: ["admin@t.io"],
};

describe("sendReportMail", () => {
  it("sends both an HTML and a plain-text part", async () => {
    const sendMail = vi.fn(async () => ({ messageId: "1" }));
    const r = await sendReportMail(report, config, { createTransport: () => ({ sendMail }) });
    expect(r.sent).toBe(true);
    const msg = sendMail.mock.calls[0][0];
    expect(msg.html).toBeTruthy();
    expect(msg.text).toBeTruthy();
    expect(msg.to).toEqual(["admin@t.io"]);
  });

  it("refuses to send while disabled", async () => {
    const sendMail = vi.fn();
    const r = await sendReportMail(report, { ...config, enabled: false },
      { createTransport: () => ({ sendMail }) });
    expect(r.sent).toBe(false);
    expect(sendMail).not.toHaveBeenCalled();
  });

  it("refuses to send with no recipient rather than throwing", async () => {
    const r = await sendReportMail(report, { ...config, to: [] },
      { createTransport: () => ({ sendMail: vi.fn() }) });
    expect(r).toMatchObject({ sent: false });
    expect(r.reason).toMatch(/recipient/i);
  });

  it("never puts the SMTP password in the returned reason", async () => {
    const r = await sendReportMail(report, { ...config, pass: "sup3rs3cret" }, {
      createTransport: () => ({ sendMail: async () => { throw new Error("535 auth failed for sup3rs3cret"); } }),
    });
    expect(r.sent).toBe(false);
    expect(JSON.stringify(r)).not.toContain("sup3rs3cret");
  });

  it("subjects the mail with the report date", async () => {
    const sendMail = vi.fn(async () => ({}));
    await sendReportMail(report, config, { createTransport: () => ({ sendMail }) });
    expect(sendMail.mock.calls[0][0].subject).toContain("2026-10-28");
  });
});

describe("settings protection", () => {
  it("keeps the SMTP password out of the settings GET response", async () => {
    const mod = await import("../../src/app/api/settings/route.js");
    const res = await mod.GET();
    const body = await res.json();
    expect(body.monitorSmtpPass).toBeUndefined();
  });

  it("lists the SMTP password as mass-assignment protected", async () => {
    const src = await import("node:fs").then((fs) =>
      fs.readFileSync("../src/app/api/settings/route.js", "utf8"));
    expect(src).toMatch(/PROTECTED_SETTING_KEYS[\s\S]{0,200}monitorSmtpPass/);
  });
});
```
